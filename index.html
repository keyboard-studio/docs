How to read this map

Camps are stops along one trail, not phases. The project is at several camps at once, and some camps get revisited as the ground shifts. Each camp card shows its own progress, what is done, and what is still on the ground in front of it.

Status badges
ShippedDone, merged, and in the studio or the record. BuildingActively being built right now. PlannedAgreed and queued — not yet started. Known issueOpen problem, honestly marked. OngoingContinuous work with no finish line.

Finished entries are tucked behind a “Show N finished” toggle on each camp so the open work stays visible first. Field notes are the short version of a ruling, a constraint, or a lesson — the GitHub link is always the full record.

Decisions, Not Documents

The decision architecture — the studio remembers decisions, and derives everything else.

Revisited
7 of 8 done · 1 to goArchitecture shipped · migration building

The work here

  • Building Spec 105 — finish the migrationWorking copy becomes purely derived (envelope v3, ghost tests removed). Phase 0 landed in PR #2292; phases P1–P9 ahead. Spec: specs/105-*.
  • Shipped DecisionSet (088)One record per author decision — the single store of author truth.
  • Shipped Pure apply() (089)Decisions applied by a pure function — same decisions in, same keyboard out.
  • Shipped Galleries as decision modules (090)Each gallery reads and writes decisions, not documents.
  • Shipped Derived steps (091)Survey steps derived from the decision state, not hard-coded flow.
  • Shipped Live extraction (092)Decisions extracted live from an existing keyboard when it becomes a base.
  • Shipped Derived keyboard (093)The keyboard itself is a derivation of the DecisionSet.
  • Shipped Base switch = retain + recalculateSwitching base keyboards keeps decisions and re-derives against the new base; answers that no longer fit are re-proposed, never silently dropped.

Field notes

The 088–093 migration never quite finished: four persisted stores of author truth grew up side by side. Spec 105 is the honest tidy-up — finish the migration rather than paper over it.

Contingency on record: if deriving ever proves too slow on an error-free process, resurrecting a stored IR is an acceptable fallback — triggered by measured latency, not by vibes.

The work here

  • Shipped Backspace as its own questionRestored as a headed question with preview; all four composition × backspace pairings generated — PR #2312.
  • Shipped Validation walk, round 3: 32 / 32 PASSAll 32 axis combinations walked end to end, with 32 real keyboard .zip packages produced as evidence.
  • Shipped Placement intelligencePer-key occupancy ledger, weighted placement rationale, and demotion proposals (core displaces convenience; convenience never demotes core) — PR #2303.
  • Shipped Touch-key ID criteria — spec 104T_ keys as a deliberate first-class idiom; the one resolver lives in contracts; all 27 tasks complete.

Field notes

Composed forms are evidence, not placement units: they show what attaches to what, then the marks series (attachments → treatment → output form) filters the placement set before the galleries.

A rule-free T_ key is a dead key — that population is a repair list, not a pattern to copy.

    Field notes

    Attribution trap, learned firsthand: the nightly soak reuses ci.yml with checkout_ref: dev, so soak runs display main’s head SHA but test dev’s tree. A red soak is dev-tree evidence, not a main failure.

    Verify before claiming: a red check is A/B-proven against a pristine base before it is blamed on a change.

    The last camp · how this crew works

    Working Together

    Principles, where things live, and how help is most useful.

    6 of 6 practices live · 0 to goOngoing by nature

    Principles

    Rule once, in the open

    Product rulings are recorded on the issue or spec and carried verbatim through spec, code, and tests.

    Defaults are proposals

    Every step proposes and asks; nothing applies silently, and nothing is silently dropped.

    Verify before claiming

    A red check is A/B-proven against a pristine base before it is blamed on a change; CI is only “resolved” when every lane is green.

    Draft-first on ruling-carrying posts

    Posts that carry a ruling are drafted and checked before they are posted.

    Push, don’t hold

    Finished, verified work gets pushed and flagged — not held locally.

    “Over and out!”

    The sign-off posted on the GitHub issue when work is feature-complete and PRed.

    Where things live

    spec.md + specs/ — feature truth.

    packages/contracts — the shared contract.

    docs/criteria.md — the review checklist.

    GitHub issues — rulings and status.

    Triage — the server /km-triage service (running since the project’s first weeks) walks open PRs; Muse’s muse-triage sweep (since 10 Oct 2026) is the same discipline under Muse’s own identity. Personal mode is only the by-hand escape hatch.

    This trailmap — the state of the project at a glance.

    The studio itself — keyboard-studio.github.io/keyboard-studio.

    How help is most useful

    Smoke-test the exact failing walk and report concretely — what you did, what happened, what you expected.

    Answer the one ruling question a crew has staged, with its options and risks laid out.

    Merges to main remain Matthew’s call — PRs land on dev first (Camp 06).

    Requests land as GitHub issues — there is no separate feedback forum; an issue is where an ask arrives and where its landing gets recorded. Contributors (e.g. Kevin) file and build through issues and PRs the same way.
